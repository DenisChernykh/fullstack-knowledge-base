# HTTP status codes

## Вопрос

Какие status codes вернуть при создании, ошибке валидации, отсутствии аутентификации, запрете, конфликте и внутренней ошибке?

## Короткий ответ

Успешное чтение обычно возвращает 200, создание — 201 с Location, успешная операция без body — 204, принятая асинхронная работа — 202. Некорректный синтаксис или входные данные — 400 либо 422 по принятому контракту. 401 означает, что клиент не аутентифицирован или credential недействителен, 403 — личность известна, но действие запрещено. 404 скрывает или сообщает отсутствие ресурса, 409 отражает конфликт с текущим состоянием, 429 — превышение лимита. Неожиданная ошибка сервера — 500, недоступная зависимость может дать 502 или 503. Главное — единая семантика и безопасное тело ошибки.

## Разбор

- Код выбирают по наблюдаемому результату на HTTP-границе, а не по имени внутреннего exception. Domain conflict часто становится 409, validation error — 400/422, отсутствующая запись — 404.
- 401 обычно сопровождается WWW-Authenticate. 403 не означает «не вошёл»: это отказ уже распознанному субъекту.
- 500 не должен раскрывать stack trace, SQL или secret. Клиенту нужен стабильный код ошибки и request ID, а подробности остаются в защищённых логах.
- Одинаковый failure mode должен иметь одинаковый status во всех controllers; mapping лучше централизовать.

## Частые уточнения

**400 или 422 для validation error?** Оба варианта встречаются. Следует выбрать и документировать один контракт; 400 проще, 422 точнее отделяет синтаксически корректный запрос с неприемлемыми данными.

**Когда возвращать 404 вместо 403?** Если раскрытие существования ресурса само по себе чувствительно. Это должно быть осознанной политикой, а не случайной разницей controllers.

**Когда уместен 503?** При временной недоступности сервиса или обязательной зависимости; при возможности полезен Retry-After.

## Где ошибаются

Частые ошибки — возвращать 200 с полем success=false, путать 401 и 403, превращать все ожидаемые конфликты в 500 и обещать клиенту retry для любой серверной ошибки.
